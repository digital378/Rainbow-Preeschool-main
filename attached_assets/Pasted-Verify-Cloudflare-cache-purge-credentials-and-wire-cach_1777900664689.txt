Verify Cloudflare cache purge credentials and wire cache purging into 
predeploy.sh. Three discrete tasks, do them in order.

TASK 1 — Verify Cloudflare credentials work

The user has added two Replit Secrets: CF_ZONE_ID and CF_API_TOKEN.
Test that the token authenticates and can purge the zone's cache.

Run in the Shell:

  curl -X POST "https://api.cloudflare.com/client/v4/zones/$CF_ZONE_ID/purge_cache" \
    -H "Authorization: Bearer $CF_API_TOKEN" \
    -H "Content-Type: application/json" \
    --data '{"purge_everything":true}'

Expected output: JSON containing "success":true and a result.id matching 
CF_ZONE_ID. Report the full response.

If the response shows "success":false or an authentication error, STOP 
and report the error verbatim. Don't proceed to Task 2.


TASK 2 — Bump edge cache TTL on HTML responses

In server/static.ts (or wherever cdn-cache-control is set for HTML 
responses), find the current value:

  'public, max-age=300, stale-while-revalidate=86400'

Change it to:

  'public, max-age=3600, stale-while-revalidate=86400'

Reason: per-POP edge caches currently expire every 5 minutes. Low-traffic 
POPs (Bangalore for our audience) don't get enough hourly traffic to 
re-warm the cache, leading to 475ms TTFB on cache misses vs 80ms on hits. 
1-hour TTL keeps caches warm between real-user requests at low-volume POPs.

Constraints:
- Only change cdn-cache-control. Do NOT change the standard Cache-Control 
  header.
- Do NOT change cache headers on bot SSR responses (server/bot-ssr.ts) — 
  those stay private, no-cache.
- Do NOT change cache headers on /api/* routes.
- Do NOT add caching to any route that currently has no-cache.

Run npx tsc --noEmit to confirm clean.


TASK 3 — Wire cache purge into predeploy.sh

Add a final step to scripts/predeploy.sh that purges Cloudflare's cache 
after a successful deploy. This ensures the new max-age=3600 TTL takes 
effect immediately on deploy rather than waiting up to an hour for old 
cached responses to expire.

Add this as a NEW final step in predeploy.sh, after all existing steps:

  # Step N — Purge Cloudflare edge cache
  if [ -n "$CF_ZONE_ID" ] && [ -n "$CF_API_TOKEN" ]; then
    echo "Purging Cloudflare cache..."
    PURGE_RESPONSE=$(curl -sX POST \
      "https://api.cloudflare.com/client/v4/zones/$CF_ZONE_ID/purge_cache" \
      -H "Authorization: Bearer $CF_API_TOKEN" \
      -H "Content-Type: application/json" \
      --data '{"purge_everything":true}')
    if echo "$PURGE_RESPONSE" | grep -q '"success":true'; then
      echo "Cloudflare cache purged successfully"
    else
      echo "WARNING: Cloudflare cache purge failed: $PURGE_RESPONSE"
      # Don't fail the deploy — purge is nice-to-have, not blocking
    fi
  else
    echo "Skipping Cloudflare cache purge (CF_ZONE_ID or CF_API_TOKEN not set)"
  fi

Important:
- This step must NOT fail the deploy if the purge fails. Log a warning, 
  exit 0, continue.
- It must NOT run if either secret is missing — log a skip message instead.
- Place it as the LAST step in predeploy.sh so it only runs after 
  everything else (build, tests, perf guard) has succeeded.
