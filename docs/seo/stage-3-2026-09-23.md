# Stage 3 rendering parity — 23 September 2026

## Scope and baseline

Compared six representative URLs on the development application before changes using three paths: a Chrome user agent requesting the **initial HTML** without executing JavaScript, a Googlebot user agent requesting the **bot HTML**, and Chromium after the **visitor page rendered**. The initial visitor HTML is intentionally an SPA shell with no page body; that alone is not evidence of an indexing failure, since Googlebot receives contentful HTML and Chromium renders the visitor page.

| URL | Before: initial HTML vs bot | Before: rendered visitor vs bot |
| --- | --- | --- |
| `/` | Homepage description differed; homepage shell had an older title and description than its rendered page | Bot H1 and description differed from the visitor hero and SEO settings; visitor still injected an FAQ schema without visible homepage FAQs |
| `/blog/what-age-start-play-school` | Homepage title, description and canonical instead of article metadata | H1 differed; visitor description contained an additional sentence |
| `/playgroup` | Homepage title, description and canonical | Visitor had 10 FAQs; bot schema had 7 differently worded answers, including fixed batch hours |
| `/contact` | Homepage title, description and canonical | Description and H1 differed; bot body had landline/head-office details absent from visitor |
| `/gallery` | Homepage title, description and canonical | Description differed; bot listed categories but omitted all 56 curated photos |
| `/preschool-admissions` | Homepage title, description and canonical | Bot gave a dated 2027–28 admission calendar while visitor showed a yearless timeline and 2026–27 admissions |
| `/faqs` | Homepage title, description and canonical | Both used the shared 30 questions, but bot body showed only category names while FAQ schema included answers |

The initial shell also lacked page-specific JSON-LD in development (production already injected it for most routes). The rendered visitor's title, canonical and robots directives were correct for the representative URLs after hydration. The previously removed hidden homepage FAQ block was not reintroduced.

## Changes

- Initial visitor HTML now takes its route-specific title, description, canonical, index directive and social metadata from the same page SEO data as bot HTML. Development and production both inject the existing route schemas into the initial shell. The SPA body is still hydrated by React.
- The homepage shell title/description/social tags and bot homepage description/H1 were aligned with its rendered SEO settings after the homepage sync guard and completion review caught pre-existing drift. The visitor's FAQ schema injection was removed because no FAQs are visible on the homepage; it is not present in either initial HTML or bot SSR. Its sitemap date now records the actual metadata change.
- Playgroup uses the same ten FAQ pairs in the visitor accordion, bot FAQ schema and visible bot body. `/faqs` and admissions render their shared schema answers in bot body text. The sampled blog article's SEO description and H1 now agree with the visitor page.
- The bot gallery contains figures for the 56 photos in the same curated gallery collection that the visitor uses. Contact bot copy no longer asserts additional landline/head-office details; the admissions bot timeline now follows the yearless periods presented to visitors. A blog age-range sentence was aligned with the admissions programme ranges.
- A real browser running Lighthouse or another supported inspection tool now receives the hydrated visitor page; a non-rendering auditor receives bot HTML. Googlebot still receives bot HTML even when its smartphone user agent contains Chrome tokens.
- Sitemap `<lastmod>` is now optional. It is present on explicitly updated pages and on blog posts with a post-specific date; unknown modification dates are omitted instead of inheriting the site-wide review date. For example, `/`, `/blog`, `/faqs`, `/playgroup`, `/preschool-admissions`, `/contact` and `/gallery` report 2026-09-23; `/about` omits `<lastmod>`; the sampled blog post retains its curated 2026-04-02 date.

## Remaining differences and rendering decision

The initial Chrome HTML still has no article or page body before hydration, by design. The bot page uses a semantic text/figure layout rather than the visitor's interactive layout; expandable visitor FAQ answers appear when opened, while bot answers are visible immediately. Other site pages may still have copy-depth differences outside this representative set. The shared FAQ content, page-specific shell metadata and parity guard reduce immediate search-signal drift; the observed remainder does not justify an immediate full rendering-architecture replacement. Reassess a unified renderer if future audits find repeated substantive drift rather than treating an unhydrated SPA shell as a failure by itself.
