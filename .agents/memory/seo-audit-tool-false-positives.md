---
name: SEO audit tool false positives (missing H1 / orphan pages / missing schema)
description: Third-party site-audit tools that present a browser-like UA but don't wait for React hydration get the empty SPA shell and misreport missing H1, orphan pages, and missing schema.
---

`server/bot-ssr.ts` serves fully-rendered HTML (with H1, internal nav links, full Organization/EducationalOrganization schema) only to user agents that either match `BOT_USER_AGENTS` or fail `looksLikeRealBrowser()`. A crawler that spoofs a Chrome/Safari-style UA (common for audit tools trying to avoid bot-blocking) but doesn't fully execute JS/wait for hydration falls through to the raw SPA shell, which has: 0 `<h1>` tags, no internal `<a href>` links (so the crawler stops after 1 page and flags every sitemap URL as "orphaned"), and only a minimal static `Article` JSON-LD (no top-level `Organization` node).

**Why:** This exact pattern has hit multiple audit tools independently (screamingfrog, sitebulb, lighthouse were fixed previously; getveritas.io's "Site Audit" hit it again in Aug 2026 with a report showing "SPA detected — results may be incomplete", 1-page crawl, and orphan/H1/schema findings that were all traceable to the un-hydrated shell).

**How to apply:** Before treating any "no H1" / "orphan pages" / "missing schema" finding from a third-party SEO tool as real, reproduce with `curl -A "<real-browser-UA>" <url>` (no JS execution) vs `curl -A "<tool-name-or-plain>" <url>`. If the browser-UA fetch is missing the content, it's a rendering-timing artifact, not a real gap — verify real content via a UA already in `BOT_USER_AGENTS` (or plain curl, which isn't a real-browser signature). Fix by adding a distinguishing substring of the tool's crawler UA to `BOT_USER_AGENTS` in `server/bot-ssr.ts`. If the exact documented crawler UA string can't be found, a best-effort substring of the tool/company name is acceptable (low collision risk with real browser UAs) — flag this assumption to the user since it isn't independently confirmed against the tool's actual request logs.
